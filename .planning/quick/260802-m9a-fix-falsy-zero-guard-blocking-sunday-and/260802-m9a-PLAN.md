# Fix falsy-zero guard in ScheduleSlotFormDialog

## Problem

User report: "the Sunday button does not work."

Reproduced against the deployed app (Tara → Schedule → Add slot):

| Clicked | Trigger shows | Hidden `weekday` input |
|---------|---------------|------------------------|
| Sunday    | Monday    | 1 |
| Wednesday | Wednesday | 3 |
| Saturday  | Saturday  | 6 |

Selecting Sunday is silently discarded — the picker stays on the Monday default.

## Root cause

`components/schedule-slot-form-dialog.tsx` guards three Base UI `Select`
handlers with a truthiness test:

```tsx
onValueChange={(value) => value && setWeekday(value)}   // line 118
onValueChange={(value) => value && setHours(value)}     // line 163
onValueChange={(value) => value && setMinutes(value)}   // line 180
```

Base UI's `Select` passes the `SelectItem`'s **raw** value to `onValueChange`,
and these items are given numbers (`WEEKDAY_OPTIONS[].value`, `HOUR_OPTIONS`,
`MINUTE_OPTIONS` are all `number[]`). The option whose value is `0` is therefore
falsy, and the guard drops the state update.

Affected options — every `0`-valued one in this dialog:
- **Sunday** (`weekday: 0`) — the reported bug
- **0 hrs** (`HOUR_OPTIONS[0]`) — a sub-hour slot (e.g. 0 hrs 30 min) is unselectable
- **0 min** (`MINUTE_OPTIONS[0]`) — can't return to a whole-hour length after picking 15/30/45

The guard's real intent is to ignore a `null` clear-selection emission, which a
null check expresses correctly without swallowing `0`.

`session-form-dialog.tsx` and `calendar-view.tsx` use the same option arrays but
pass values through without a guard, so they are **not** affected — out of scope.

## Tasks

### Task 1 — Replace the truthiness guards with null checks

- **files:** `components/schedule-slot-form-dialog.tsx`
- **action:** Change all three handlers to `value != null && setX(String(value))`.
  `String(...)` normalises the number Base UI emits back to the `string` the
  `useState<string>` declarations and the hidden `<input>` values expect —
  currently days 1–6 write a `number` into a state slot typed `string`.
- **verify:** `npx tsc --noEmit` and `npm run lint` clean.
- **done:** No truthiness guard remains on a `Select` `onValueChange` in this file.

### Task 2 — Prove the fix against the running app

- **files:** none (verification only)
- **action:** Drive the dialog with Playwright: select Sunday, 0 hrs and 0 min,
  and assert the trigger label and the hidden inputs update. Confirm a
  Sunday slot round-trips to the DB and renders as "Sundays, …".
- **verify:** Sunday selection sets `weekday=0`; a saved Sunday slot reads back.
- **done:** Reproduction case from the table above now passes.

## Must haves

- Sunday is selectable and persists as `weekday=0`.
- `0 hrs` and `0 min` are selectable.
- Days 1–6 and non-zero lengths keep working (no regression).
- No change to `session-form-dialog.tsx` or `calendar-view.tsx`.
