<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client form → session Server Actions | Untrusted FormData (studentId, date, durationMinutes, notes) crosses into the DB write path |
| client → money computation | Client must never dictate the billed amount |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | addSessionAction / editSessionAction money computation | mitigate | Server independently re-fetches `students.rateCents` from the DB and computes `amountCents = round(durationMinutes × rateCents / 60)`; the action never reads amountCents/rateCents from FormData. Verified by the `! grep formData.get("amountCents"/"rateCents")` gate in Task 1. |
| T-02-02 | Tampering / Elevation | crafted studentId (nonexistent or archived) via hidden input | mitigate | Server verifies the submitted studentId resolves to an existing student row before insert/update; returns a studentId field error otherwise (mirrors editStudentAction id validation). |
| T-02-05 | Tampering (input validation) | all session Server Action inputs | mitigate | zod `safeParse` at the boundary: studentId positive int, date `z.iso.date()`, durationMinutes positive int (>0), notes optional bounded string (max 1000). ASVS V5. |
| T-02-07 | Denial / data-integrity | deleteSessionAction hard delete | mitigate | Id guard (positive integer) before `db.delete`; scoped to a single `sessions.id`; no cascade to students (FK is restrict). Single-user model — no cross-tenant authorization needed (ASVS V4 satisfied by the middleware gate). |
| T-02-08 | Spoofing | new session mutations behind auth | accept | All routes/actions run behind the existing iron-session `middleware.ts` gate established in Phase 1; no new session logic added. |
</threat_model>
