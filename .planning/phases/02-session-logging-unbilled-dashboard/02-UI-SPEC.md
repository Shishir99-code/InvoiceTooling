## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn (already initialized — `components.json` present) |
| Preset | `base-nova` (neutral base color, Lucide icons, `@base-ui/react` primitives) |

**New shadcn components required this phase** (per 02-RESEARCH.md Standard Stack):
`combobox`, `select`, `popover`, `calendar` — install via
`npx shadcn@latest add combobox select popover calendar`. All will render with the
`render`-prop trigger idiom already established in `components/ui/dialog.tsx`
(`<PopoverTrigger render={<Button variant="outline" type="button" />}>`), matching
this repo's Base UI style — do not copy Radix `asChild` examples from generic shadcn
tutorials.

## Spacing Scale

Declared values (must be multiples of 4) — unchanged from Phase 1, no new scale introduced:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding (e.g. gap-1 in table cells) |
| sm | 8px | Compact element spacing (gap-2: form field labels, action button pairs) |
| md | 16px | Default element spacing (gap-4: form fields, card padding `p-4`) |
| lg | 24px | Section padding (`mb-6` heading-to-content gap, matches Phase 1 pages) |
| xl | 32px | Layout gaps (page vertical padding `py-8`) |
| 2xl | 48px | Major section breaks (`py-12` on larger viewports) |
| 3xl | 64px | Page-level spacing (empty-state vertical padding `py-16`) |

**Exceptions:**
- **44px minimum tap target** on the Sessions/Dashboard per-student expand/collapse
  row header on mobile — the clickable header row (name + summary chip) must have
  `min-h-11` (44px) even though its visual content is shorter, per WCAG 2.5.5 target
  size and this app's mobile-first usage pattern (tutor checking the dashboard on
  her phone between lessons).
- No other exceptions — session/dashboard tables reuse `student-table.tsx`'s exact
  `p-4` card / `p-2` cell paddings.

## Typography

Reused verbatim from the live Phase 1 codebase (`app/page.tsx`, `student-table.tsx`,
`components/ui/dialog.tsx`, `components/ui/label.tsx`) — no new sizes introduced.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label / small / error | 14px (`text-sm`) | 500 (`font-medium`, shadcn `Label` default) | 1.0 (`leading-none`) for labels; 1.5 for error/help text |
| Body | 16px (`text-base`) | 400 (regular, no weight class) | 1.5 |
| Heading | 20px (`text-xl`) | 600 (`font-semibold`) | 1.2 (`leading-tight`) |
| Display | 28px (`text-[28px]`) | 600 (`font-semibold`) | 1.2 (`leading-tight`) — page `<h1>` only |

**Weight note (2-weight content rule):** New Phase 2 copy (headings, body, empty
states, error text) uses exactly two weights — **regular 400** for body/copy and
**semibold 600** for headings/emphasis — identical to Phase 1's `app/page.tsx`. A
third weight, **medium 500**, appears only inside shadcn's own primitives (`Button`,
`Label`, `TableHead`, `DialogTitle`) and is inherited unchanged from
`components/ui/*` — do not introduce `font-medium` in new page-level/custom copy;
reserve it for shadcn component internals only, exactly as Phase 1 does.

**Dialog title** (`Log Session` / `Edit Session` modal, per `DialogTitle` in
`components/ui/dialog.tsx`): 16px (`text-base`), `font-medium` (500, inherited
shadcn default, not part of the 2-weight content rule above), `leading-none`.

## Color

Reused verbatim from the live Phase 1 codebase. **Important duality, carried
forward unchanged:** shadcn's own primitives (`Button`, `Dialog`, `Table`) use the
oklch CSS-variable tokens defined in `app/globals.css` (`--primary`, `--muted`,
`--destructive`, etc.), while Phase 1's page-level custom code hardcodes literal
Tailwind `blue-600`/`red-600`/`zinc-*` classes instead of those tokens. Phase 2 must
follow the **same duality** — do not "fix" it by switching page-level accents to
the oklch tokens; that would visually diverge from the Students/Archived pages
built in Phase 1.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#ffffff` / `oklch(1 0 0)` (`bg-background`, `bg-white`) | Page background, dialog/table container fills |
| Secondary (30%) | `zinc-50`–`zinc-200` (`#fafafa`–`#e4e4e7`), white cards with `border-zinc-200` | Table containers, mobile stacked cards, nav bar bottom border, dialog footer (`bg-muted/50`) |
| Accent (10%) | `#2563eb` (Tailwind `blue-600`) | Reserved for: primary CTA buttons ("Log Session", "Save Changes"), active top-nav tab (text + 2px bottom border), the Students/Archived sub-tab active state, "Restore"-style link-styled buttons. **Never** apply to plain body text, borders, or non-interactive decoration. |
| Destructive | `#dc2626` (Tailwind `red-600`) | Reserved for: "Delete Session" confirm button, inline field-validation error text (`text-red-600` — matches `student-form-dialog.tsx`'s exact pattern, NOT the shadcn `--destructive` oklch token used by `Button variant="destructive"`, which is unused on these pages). |

Accent reserved for: **"Log Session" / "Save Changes" primary buttons, the active
Students / Dashboard / Sessions top-nav item (text + underline), the nested
Students/Archived active sub-tab, and single-click non-destructive link-style
actions (e.g. a future "view session" link)** — never for all interactive
elements generally.

| Info note — Dashboard with zero sessions app-wide | **"No sessions logged yet — amounts will appear here once you log your first session."** — `text-sm text-zinc-600` line under the page `<h1>`; the full roster still renders below at $0.00 / 0 hrs (D-12), this is NOT a blocking full-page empty state |

## Data Formatting Conventions

*(Addendum beyond the base template — required for consistency across the new
Session/Dashboard tables; not present in Phase 1 since it had no duration/money
aggregate to format.)*

| Value | Format | Example | Rationale |
|-------|--------|---------|-----------|
| Money | `formatCents(cents)` → `$X.XX`, extracted from `student-table.tsx`'s inline `formatRate` into a shared `lib/format.ts` helper (per CONTEXT.md Claude's Discretion) | `$75.00` | Reused verbatim, single source of truth for all money display (session row amount, dashboard totals, future Phase 3 invoice) |
| Duration | `formatDuration(minutes)` → `"{h} hr{s} {m} min"`, omitting the zero part (`"1 hr 30 min"`, `"45 min"`, `"2 hrs"`, `"1 hr"`) | `1 hr 30 min` | Mirrors the tutor's own mental model (D-05: "an hour and a half"), not a decimal-hours display — keeps input vocabulary (hours+minutes dropdowns) and output vocabulary consistent |
| Date | `date-fns format(date, "PPP")` for display (e.g. "July 3, 2026"); `format(date, "yyyy-MM-dd")` for the hidden form field/DB round-trip | Display: `July 3, 2026`; stored: `2026-07-03` | Matches 02-RESEARCH.md Pattern 3/Pitfall 2 exactly — never round-trip the *stored* value through a JS `Date` object |

## Surface Specifications

*(Addendum beyond the base template — the 5 phase surfaces named in the
orchestrator prompt each get an explicit, unambiguous contract here so the
executor has no open design questions.)*

### 1. App-level top nav (D-02)
- Replaces the inline Students/Archived tab strip in `app/page.tsx` /
  `app/archived/page.tsx` with a shared nav in the new `app/(app)/layout.tsx`
  route group (per 02-RESEARCH.md Pattern 1).
- **Three flat items, in this order:** Students · Dashboard · Sessions.
  **Archived is NOT a fourth item** — it stays nested as the existing sub-tab pair
  underneath the Students page content, unchanged from Phase 1's implementation
  (just rendered below the new top nav instead of at the very top of the page).
- Visual style: horizontal flex row, `border-b border-zinc-200`, each link
  `pb-2 text-base font-medium` (16px/500, matching the existing tab typography).
  Active item: `text-blue-600 border-b-2 border-blue-600` (accent, -mb-px to sit
  flush on the container's border). Inactive: `text-zinc-600 hover:text-zinc-900`.
- Container: `mx-auto w-full max-w-3xl px-4`, consistent with every page's content
  width (matches `app/page.tsx`'s `max-w-3xl`).
- Mobile: no hamburger/drawer — 3 links comfortably fit a flex row at all widths
  this app targets (phone portrait included); if the row ever overflows, allow
  horizontal scroll (`overflow-x-auto`) rather than building a collapsed-menu
  pattern for only 3 destinations (avoids over-engineering for a single-user app).
- `app/layout.tsx` (root) stays nav-free; `/login` never renders this nav
  (02-RESEARCH.md Pitfall 6).

### 2. Log Session modal (D-03..D-07, D-14)
Cloned from `StudentFormDialog`/`components/ui/dialog.tsx` exactly (same
`Dialog`/`DialogContent`/`DialogHeader`/`DialogFooter` shell, same
`useActionState` + "close only on real success" pattern, same
`noValidate` + server-side-zod-is-sole-gate rule).

- **Title:** "Log Session" (add) / "Edit Session" (edit) — 16px/500 (`DialogTitle` default).
- **Field order (top to bottom):**
  1. **Student** — shadcn `Combobox` (Base UI variant, 02-RESEARCH.md Pattern 2).
     Placeholder: "Search student…". Each item renders `"{name} — {parentEmail}"`
     exactly (D-04's disambiguator). Selecting an item populates a hidden
     `studentId` input bound to `students.id` (never the name string). Label: "Student".
  2. **Length** — two shadcn `Select` dropdowns side-by-side (`flex gap-2`):
     Hours (`0`–`8`, suffix "hr"/"hrs") and Minutes (`0`/`15`/`30`/`45`, suffix
     "min"), combined into a single hidden `durationMinutes` input before submit
     (02-RESEARCH.md Pattern 4). Label: "Length".
  3. **Date** — shadcn `Popover` + `Calendar` (Pattern 3), trigger button shows
     `format(value, "PPP")`, defaults to today (D-06). Label: "Date".
  4. **Notes** — optional plain `<textarea>` (reuse `Input`-equivalent styling,
     3 rows), placeholder: "Add any notes about this session (optional)".
     Label: "Notes (optional)".
- **Live amount preview (resolves CONTEXT.md's open discretion item):**
  **Include it.** Directly under the Length row, render a small
  `text-sm text-zinc-600` line: `"≈ $X.XX"`, computed **client-side only** from
  `(hours*60+minutes) * selectedStudent.rateCents / 60`, using the `rateCents`
  already present on the combobox-selected student object. This is a
  non-authoritative estimate purely for the tutor's in-the-moment feedback while
  picking hours/minutes — it is never submitted as form data, and the Server
  Action independently re-fetches `rateCents` and computes the real
  `amountCents` server-side (02-RESEARCH.md Pitfall 1 still fully applies). Label
  the preview literally with the "≈" glyph so it never reads as an authoritative
  total. Render nothing (no "≈ $0.00") until a student is selected.
- **Footer:** "Discard" (outline) + primary submit button (blue-600), identical
  to `StudentFormDialog`'s footer.
- Trigger button: same visual treatment as "Add Student" —
  `bg-blue-600 text-white hover:bg-blue-700`, placed top-right of the Sessions
  page (mirrors `app/page.tsx`'s Add Student trigger position). The Dashboard
  page does NOT get its own "Log Session" trigger — its "path to edit" (D-11)
  opens the same modal in **edit** mode only, reached via each expanded
  session row's Edit action.

### 3. Sessions page (D-08, D-09, D-10)
- Route: `app/(app)/sessions/page.tsx`. Heading: `<h1>` "Sessions" (28px/600,
  identical to "Students"/"Archived Students" headings), "Log Session" trigger
  top-right (see Surface 2).
- **Grouped by student**, one collapsible group per student (active students
  first; archived students' historical sessions included per-group with a small
  "Archived" badge next to their name, per 02-RESEARCH.md Open Question 2's
  recommended default — preserves history visibility without a separate toggle).
- **Group header row** (the accordion trigger): student name (16px/500) + a
  small muted count chip ("{n} sessions") + the group's unbilled total via
  `formatCents` — clickable, `min-h-11` (44px, the spacing exception above),
  chevron-down/right icon (`lucide-react` `ChevronDown`, rotates 180° when open
  via a simple `"use client"` toggle component — no new accordion library, a
  plain `useState`-driven disclosure is sufficient at this scale). **Default:
  all groups start collapsed** (glance-able list of names first, consistent with
  the Dashboard's "collapsed by default" per D-11).
- **Expanded content:** reuses `StudentTable`'s exact responsive table→card
  pattern (table md+, stacked cards below md) with columns: Date | Length |
  Amount | Notes | Actions. Actions = "Edit" (reopens the Log Session modal
  pre-filled, D-09) + "Delete" (opens the delete-confirm dialog, D-10).
- **Full-page empty state** (zero sessions logged for ANY student yet): follow
  the Copywriting Contract's "No sessions yet" entry, full `py-16` centered
  layout identical to `StudentTable`'s empty-state block.
- **Per-group empty state** (a specific student has zero sessions, but others
  exist): the group still renders and is expandable; its expanded body shows
  only the "No sessions logged for {studentName} yet." note (Copywriting
  Contract), no table/cards.

### 4. Dashboard page (D-11, D-12, D-13)
- Route: `app/(app)/dashboard/page.tsx`. Heading: `<h1>` "Dashboard" (28px/600).
  No primary CTA button in the header (this page is a glance/summary view, not
  an entry point for new data — matches D-11's "path to edit," not "path to add").
- **Shows ALL active students** (D-12), one row/card per student, same
  collapsible group mechanism as Surface 3 (identical header row treatment:
  name + count chip + `formatCents` total, 44px tap target, chevron icon,
  collapsed by default).
- **Sort order:** most-owed-first by `unbilledAmountCents` descending, **$0
  students fall to the bottom**, alphabetical tiebreak (mirrors 02-RESEARCH.md
  Pattern 6's `orderBy(desc(unbilledAmountExpr), asc(students.name))` exactly —
  this is a pure reflection of that server-side ordering, no client re-sort).
- **Row/card content (collapsed state):** student name, **unbilled hours**
  (via `formatDuration`) and **amount owed** (via `formatCents`) side by side.
  A $0/0-hour student still renders — never hidden (D-12) — with
  `text-zinc-600` (de-emphasized) instead of the default `text-zinc-900`, so
  the eye is drawn to students who owe money first without literally removing
  the $0 rows.
- **Expanded content:** the underlying **unbilled sessions only** (D-13 —
  never billed ones) for that student, same table→card pattern as Surface 3
  minus the "Delete" action column reduced to just "Edit" (Claude's
  Discretion, resolved: include Edit here too, since D-11 explicitly says
  "with a path to edit" — Delete is available from the Sessions page,
  avoiding two destructive-action entry points for the same row and keeping
  the Dashboard focused on "who owes what," not full session management).
- **Info note** for the all-$0 (zero sessions logged anywhere) scenario: see
  Copywriting Contract — a single de-emphasized line under the `<h1>`, not a
  blocking empty state, since the roster still fully renders below it.

### 5. Delete Session confirmation (D-10)
- Clones `ArchiveConfirmDialog` exactly (same `Dialog` shell, same
  bound-Server-Action-on-submit pattern), but performs a **hard delete**
  (`DELETE`, not `UPDATE archived=true`).
- Copy: see Copywriting Contract's "Destructive confirmation — Delete Session"
  row. Trigger: "Delete" outline button (`sm` size), same placement as the
  "Archive"/"Edit" action pair in `StudentTable`'s `renderActions`.
