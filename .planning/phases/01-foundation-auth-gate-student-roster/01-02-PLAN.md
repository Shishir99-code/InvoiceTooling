<objective>
Build the single-shared-password auth gate — the walking skeleton's first user-facing end-to-end capability. A visitor is redirected to `/login`, submits the password, is rate-limited on repeated failures, and on success receives a secure iron-session cookie and lands on a protected `/` roster page that reads live student rows from Neon. This proves the full stack (middleware → Server Action → DB write to login_attempts → DB read of students → protected render) works end to end.

Purpose: Implements AUTH-01..04 — the choke point that protects every route added in this and all later phases. Establishes the middleware + Server Action + iron-session pattern.
Output: Working login flow, rate limiter, session persistence, and a protected roster page (thin — full CRUD arrives in Plan 03).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| unauthenticated client → /login Server Action | Untrusted password guesses cross here |
| client → every protected route → middleware | Session cookie is validated before any route renders |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Spoofing | /login brute-force guessing | mitigate | Postgres `login_attempts` rate limiter keyed by `ipAddress()`, 5 attempts / 15-min lockout; survives serverless cold starts (in-memory counter would silently no-op — Pitfall 3). Requires a high-entropy `APP_PASSWORD`. |
| T-02-02 | Information Disclosure | password comparison timing | mitigate | `crypto.timingSafeEqual` on equal-length buffers, never `===` — constant-time compare. |
| T-02-03 | Tampering | session cookie forgery/tampering | mitigate | `iron-session` encrypted + signed cookie; any tamper fails to unseal and is treated as no session. |
| T-02-04 | Elevation of Privilege | direct route access bypassing login | mitigate | `middleware.ts` matcher is deny-by-default covering all routes except `/login` + static assets — no route opts out by omission (AUTH-03). |
| T-02-05 | Elevation of Privilege | CVE-2025-29927 x-middleware-subrequest bypass | accept | Not applicable — Next.js 16.2.10 (locked) is far past the patched threshold (fixed 15.2.3); mitigation is staying on the locked version, no extra code. |
| T-02-06 | Information Disclosure | APP_PASSWORD leaking into client bundle | mitigate | `process.env.APP_PASSWORD` is read only inside the `"use server"` action; never imported into a client component or the login page's client code. |
</threat_model>
