<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client form → addStudentAction / editStudentAction | Untrusted student name / rate / email cross a network boundary (Server Actions are callable like functions but are a network boundary) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Tampering | SQL injection via student form fields | mitigate | Drizzle ORM parameterized query builder — no raw string-interpolated SQL anywhere; values pass through `.values(...)`/`.set(...)`. |
| T-03-02 | Tampering | invalid/malicious input reaching the DB | mitigate | `zod` v4 validation at the Server Action boundary before any write — name `min(1)`, rate `positive()`, email `z.email()` format (D-13); client-side validation is never trusted (server is source of truth). |
| T-03-03 | Elevation of Privilege | unauthenticated mutation of students | mitigate | Both actions execute only behind the `middleware.ts` gate (Plan 02) — an unauthenticated request to any route hosting these actions is redirected to `/login`. |
| T-03-04 | Tampering | float rounding drift in money | mitigate | `Math.round(rateDollars * 100)` into an integer `rate_cents` column — avoids `19.99 * 100 === 1998.999…` drift (D-07 / SESS-05). |
</threat_model>
