## Phase Objective

Deliver a **scheduled invoicing layer** on top of Phase 3's manual invoice generation: the tutor sets a **monthly cadence** (day of month) and a background job auto-generates a **frozen invoice for every student with unbilled sessions** on that day — reusing Phase 3's atomic generation. Auto-generated invoices land in Invoice History marked "Auto" and "Not sent yet" so the tutor has a clear review queue; she stays the one who hits send (the emotional core of the phase).

#### Plan 05: Cadence Cron Job
**Objective:** Build the RINV-02 cadence engine that runs on the daily cron, auto-generating invoices for all students with unbilled sessions on/after the cadence day.

**Deliverables:**
- Created `lib/invoice/cadence.ts`:
  - Exported `runInvoiceCadence()` — monthly HWM self-healing cadence engine
  - Guard order (F5 exact):
    1. Load settings; if toggle off → return early (no-op)
    2. Resolve current month + day in `settings.timezone` (never UTC)
    3. Check HWM: if already fired this month → return early
    4. Resolve effective cadence day (handles "last day" via `getDaysInMonth`, clamps specific day via `Math.min`)
    5. If today's day < effective day → return early (not yet this month)
    6. RUN: Query DISTINCT students with unbilled sessions
       - For each, call `generateInvoiceForStudent` with `autoGenerated: true` (no `throughDate`)
       - Per-student try/catch: failures counted as "skipped", never block the batch
    7. After loop, set `lastInvoicedMonth` to current `YYYY-MM`
    8. Return `{ generated, skipped, ranThisMonth: true }`
- Folded `runInvoiceCadence` into existing `/api/cron/auto-log` route:
  - Runs `runAutoLog()` first (so today's scheduled sessions exist)
  - Then runs `runInvoiceCadence()`
  - Returns `{ ok: true, autoLog, cadence }`
  - Reuses `isAuthorizedCronRequest` (CRON_SECRET) bearer auth
  - `vercel.json` unchanged (still one daily cron)
  - `middleware.ts` unchanged (`api/cron` already exempt)

## Technical Highlights

### Atomicity & Double-Billing Guard
- All invoice generation (manual and auto) flows through the same `db.batch` CTE from Plan 3
- No `db.transaction` anywhere (throws at runtime on neon-http)
- Double-billing guard: INSERT gated on all target sessions still unbilled; UPDATE gated on EXISTS
- Two concurrent generations (or manual + cron overlap) safely abort the second with "race-lost"

### Timezone Correctness
- Cadence day resolved in `settings.timezone` (never UTC)
- Prevents off-by-one fires around midnight UTC boundaries

### Idempotency & Self-Healing
- Monthly `lastInvoicedMonth` HWM guarantees at most one run per calendar month
- Vercel Hobby cron is daily-only, imprecise, may skip: the HWM catches up on next day (self-heals)
- Strict "skip if missed" model was rejected — silently drops a whole month on a cron skip

### Per-Student Blast Radius
- Cadence job wraps each student's generation in try/catch
- One student's failure never blocks the rest (pattern from Phase 5 auto-log)

### Never Auto-Sends
- App inserts `sent = false` for all new auto-generated invoices
- "Sent" is a best-effort local flag, not a delivery confirmation
- User stays the one who clicks send (opens Gmail draft)
- Opening the draft optimistically marks `sent = true` (D-09)
