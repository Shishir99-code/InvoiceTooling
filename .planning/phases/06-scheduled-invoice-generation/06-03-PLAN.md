<threat_model>
ASVS L1 — refactor of an existing money-writing path; behavior must be preserved.
- **Double-billing / race integrity:** the extraction copies the CTE guard verbatim (INSERT gated on
  all targets still unbilled; UPDATE gated on `EXISTS (SELECT 1 FROM ins)`), so two concurrent
  generations (or a manual + cron overlap) still cannot double-bill a session — the second sees zero
  unbilled targets and inserts nothing (`race-lost`). Verified by the guard-present acceptance
  criterion.
- **Server-authoritative snapshot:** the helper re-SELECTs sessions/student/settings server-side and
  freezes totals from stored `amountCents` — no client-supplied total, session list, or `auto/sent`
  value is trusted (T-03-04 precedent). `auto_generated`/`sent` are set by the server only.
- **Atomicity primitive:** stays on `db.batch` (neon-http-safe); no `db.transaction` is added, avoiding
  the runtime-throw path the Phase-3 comments warn about.
- **No new external input or secret** — the manual boundary is still just the zod-parsed studentId.
