# Phase 6 Plan 3: Factor out the Atomic Generation Core — SUMMARY

**One-liner:** Extracted the Phase-3 double-billing-guarded db.batch CTE into a reusable `generateInvoiceForStudent` helper so both the manual Server Action and the cadence cron (Plan 5) call the same atomic generation path with identical race/integrity guarantees.

## Execution

### Task 1: Create generateInvoiceForStudent helper

**Status:** ✓ Complete

- **File:** `lib/invoice/generate.ts` (194 lines)
- **Exports:**
  - `type GenResult` — discriminated union: `{ ok: true; invoiceId, parentEmail, renderedSubject, renderedBody }` | `{ ok: false; reason: "no-sessions" | "no-student" | "race-lost" | "error" }`
  - `async function generateInvoiceForStudent(opts: { studentId, autoGenerated, throughDate? }): Promise<GenResult>`
- **Key implementation details:**
  - Re-SELECTs unbilled sessions server-side (T-03-04 anti-pattern enforcement)
  - Early returns with `ok: false` for no-sessions, no-student cases
  - Freezes the immutable snapshot: totalCents (sum of stored amountCents), periodStart/End, lineItems jsonb, renderedBody/Subject
  - Runs the exact same `db.batch([db.execute(sql\`WITH target … ins … UPDATE sessions …\`)])` CTE from Phase 3
  - **CTE now includes `auto_generated, sent` columns** in the INSERT (Plan 01 requirement):
    - `auto_generated` receives `${opts.autoGenerated}` (false for manual, true for cron)
    - `sent` receives `false` (all new invoices start unsent — D-08/F8)
  - **Double-billing guard preserved unchanged:** `WHERE (SELECT count(*) FROM target) = ${sessionIds.length}` gates the INSERT; UPDATE is gated on `EXISTS (SELECT 1 FROM ins)`
  - Returns `{ ok: false, reason: "race-lost" }` if CTE inserted zero rows (another generation claimed the sessions)
  - On success returns `{ ok: true, invoiceId, parentEmail, renderedSubject, renderedBody }`
  - **Does not call `revalidatePath` or `redirect`** — those stay in the Server Action layer (cron has no request scope)
- **Accepts but does not use `throughDate`** — marked with `// Plan 04: throughDate cutoff` comment for insertion point in next phase

**Verification:**

- ✓ `npm run lint` exits 0 (no unused imports)
- ✓ Function exports match spec; uses `db.batch`, never `db.transaction`
- ✓ CTE column list includes `auto_generated, sent` with correct SELECT values
- ✓ Double-billing guard present unchanged
- ✓ Early-return pattern for all four failure reasons
