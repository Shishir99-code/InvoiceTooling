<threat_model>
ASVS L1 — foundation plan (additive schema + one data backfill), minimal attack surface.
- **Destructive migration risk:** additive-only (new nullable / NOT-NULL-default columns) → push
  cannot drop or rewrite existing data; `--accept-data-loss` is never passed. The backfill is a
  single idempotent `UPDATE invoices SET sent = true` (re-runnable with no harm).
- **Sent-state integrity:** `sent` and `auto_generated` are server-only columns — no client input
  path touches them in this plan; later inserts set them explicitly (Plan 03) and only the
  server mark-sent action flips `sent` (Plan 06). Existing rows default-then-backfilled to a safe
  "already sent" state so the review queue starts empty of false positives.
- **Secret handling:** the backfill uses `DATABASE_URL` from env (never hard-coded), matching the
  existing driver. No new secret is introduced (`CRON_SECRET` from Phase 5 is reused later).
- No new auth surface, no external request handling in this plan.
</threat_model>
