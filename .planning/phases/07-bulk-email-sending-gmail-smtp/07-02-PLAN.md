# 07-02: Settings UI — Gmail Credential Setup

**Wave**: 2 (depends on Wave 1)

**Goal**: Add "Email Delivery" section to Settings page with Gmail App Password input, verification status, and update/revoke controls.

**Requirements**: BULK-01 (credential management), BULK-05 (verification display)

## Tasks

### T1: Add email delivery settings form component
- File: `components/email-delivery-form.tsx` (new)
  - Form displays:
    - **Status badge**: "Not configured" | "Verified ✓" | "Needs setup" (color: gray/green/amber)
    - **Gmail user email input** (read-only or editable, depending on UX decision—recommend read-only since it's the invoice sender)
    - **App Password input** (type="password", placeholder shows format hint `xxxx xxxx xxxx xxxx`)
    - **Action buttons**: "Save & Verify" (primary), "Revoke" (secondary, only if configured)
  - On form submit:
    1. Validate email + app password format client-side
    2. Call `updateGmailCredential(appPassword, gmailUserEmail)` Server Action
    3. On success: show toast "Email verified ✓", update status badge to green
    4. On error: show toast with error message (e.g., "Invalid credentials" or "Gmail rate limited")
  - "Revoke" button: confirm dialog, then clear credential (set to null/empty via Server Action variant)

**Acceptance**: Form renders on Settings page; can input App Password and see verification status update after submit.

---

### T2: Integrate into Settings layout
- File: `app/(app)/settings/page.tsx` (update existing)
  - Add new section after "Zelle Handle" section:
    ```
    ## Email Delivery
    <EmailDeliveryForm />
    ```
  - Wire up existing settings fetch to include `gmailVerified`, `gmailLastError`
  - Pass to component as props

**Acceptance**: Settings page shows new section; form is interactive.

---

### T3: Add error display for verification failures
- Component: `email-delivery-form.tsx` (extends T1)
  - If `gmailLastError` is set (credential saved but verification failed):
    - Show inline error box below form: "Verification failed: {error}"
    - Offer "Retry" button to re-verify without re-entering the full password
  - Implement `verifyGmailCredential()` Server Action (no params, just verify current stored credential)

**Acceptance**: If credential is invalid, user sees error and can click "Retry" to re-verify.

---

### T4: Styling + accessibility
- Use shadcn/ui Input, Button, Badge components (already in project)
- Color scheme: green badge for verified, amber for unverified, red for error
- Password input shows/hide toggle (eye icon via shadcn)
- Clear copy: "Gmail will send from your account — parents see emails from you, not the app"
- Link to Gmail App Passwords help: `https://myaccount.google.com/apppasswords` with tooltip

**Acceptance**: Form looks polished, follows project design system (slate/teal accent from CLAUDE.md), accessible keyboard nav.
