# 07-04: Bulk Send Server Action & Error Handling Polish

**Wave**: 4 (depends on Waves 1, 2, 3 complete)

**Goal**: Implement `sendBulkInvoices` Server Action with robust error handling, per-invoice retry strategy, and user-facing success/failure messaging.

**Requirements**: BULK-03 (bulk send action), BULK-04 (error handling), BULK-05 (feedback)

## Tasks

### T1: Implement `sendBulkInvoices` Server Action
- File: `lib/actions/email.ts` (new or in `invoices.ts`)
  - Signature:
    ```typescript
    export async function sendBulkInvoices(
      invoiceIds: number[]
    ): Promise<{
      ok: boolean;
      sent: number;
      failed: number;
      errors: Array<{ invoiceId: number; recipientEmail: string; error: string }>;
    }>
    ```
  - Validation:
    1. Verify auth (user logged in via middleware)
    2. Validate `invoiceIds` is non-empty array of positive integers
    3. Fetch full invoice rows from DB for each ID (re-fetch, never trust client-echoed data)
    4. Verify each invoice exists and belongs to this user (check studentId relationships if multi-user; for single user, just check existence)
    5. Verify each invoice is NOT already marked sent (defensive; optional per UX)
  - Fetch Gmail credential from settings:
    1. Load `settings.gmailAppPassword`, `settings.gmailUserEmail`, `settings.gmailVerified`
    2. If `gmailVerified === false`, return error: "Email not verified. Set up Gmail in Settings first."
    3. If credential missing, return error: "No Gmail credential found."
  - Send loop (per-invoice error isolation):
    ```typescript
    const results = { sent: 0, failed: 0, errors: [] };
    for (const invoice of invoices) {
      try {
        await sendInvoiceViaGmail({
          invoice,
          gmailAppPassword: decrypt(settings.gmailAppPassword),
          gmailUserEmail: settings.gmailUserEmail,
        });
        
        // Mark invoice sent (ONLY if send succeeded)
        await db.update(invoices)
          .set({ sent: true })
          .where(eq(invoices.id, invoice.id));
        
        results.sent++;
      } catch (error) {
        results.failed++;
        results.errors.push({
          invoiceId: invoice.id,
          recipientEmail: invoice.parentEmail || 'unknown',
          error: error.message || 'Unknown error',
        });
        // Continue to next invoice; do NOT stop
      }
    }
    ```
  - Return results; revalidate cache for `/history` and `/dashboard`

**Acceptance**: Can call with array of invoice IDs; returns sent/failed count; failed invoices logged with error details.

### T2: Error mapping & user-friendly messages
- File: `lib/actions/email.ts` (extends T1)
  - Map Gmail SMTP error codes to clear user messages:
    - `EAUTH` → "Gmail credential invalid or expired — update in Settings"
    - `ETIMEDOUT` → "Network timeout — check connection and retry"
    - `ENOTFOUND` → "Unable to reach Gmail servers — try again later"
    - `454` or `serviceUnavailable` → "Gmail rate limited — you can send ~100 emails/day. Try again tomorrow."
    - `Invalid recipient` or `550` → "Parent email invalid or blocked by Gmail"
    - Default → "Failed to send: {error.message}" (truncate to ~100 chars)

**Acceptance**: Error messages are non-technical; user knows what to do (e.g., "rate limited — retry tomorrow").

### T3: Defensive checks & data integrity
- Add to action:
  1. **No double-send**: Before marking sent, check invoice.sent !== true (defensive; should not happen but catch it)
  2. **Stale credential check**: If `updateGmailCredential` ran recently (within 1 hour?), assume fresh verify; otherwise warn
  3. **Email format validation**: Reject invoice if `parentEmail` is malformed (simple regex or `email-validator` library)
  4. **Rate limiting**: Log send counts per day (optional; can store in a simple in-memory counter or settings.lastSendDayCount); if >100/day, warn but allow (Gmail will reject at SMTP level)

**Acceptance**: Defensive checks pass; no silent failures.

### T4: Logging & observability
- Add basic logging to help with debugging:
  - Log start: `console.log(`Starting bulk send for ${invoiceIds.length} invoices`)`
  - Log per-invoice success: `console.log(`Sent invoice ${invoiceId} to ${recipientEmail}`)`
  - Log per-invoice failure: `console.warn(`Failed invoice ${invoiceId}: ${error.message}`)`
  - Log summary: `console.log(`Bulk send complete: ${sent} sent, ${failed} failed`)`
- Optional: Store summary in analytics/event log (not required for v1, but good practice)

**Acceptance**: Console shows clear logs of send process for debugging.

### T6: Rollback & error recovery UX
- If all invoices fail:
  1. Show error banner: "No invoices sent — {primary error reason}"
  2. Selection remains; user can fix (e.g., update credential in Settings) and retry without re-selecting
- If partial success (some sent, some failed):
  1. Show success toast: "Sent X invoices; Y failed"
  2. Table refreshes; successfully-sent invoices marked as sent
  3. Failed invoices remain selected for easy retry

**Acceptance**: User can retry without re-selecting; clear recovery path.
