<threat_model>
ASVS L1 — foundation plan (schema + pure helper), minimal attack surface.
- **Destructive migration risk:** additive-only (new table + nullable column) → push cannot
  drop or rewrite existing data; mitigated by keeping the edit additive and reviewing the
  push output before proceeding. No `--accept-data-loss` flag is used.
- **FK cascade → silent history loss:** slot→session and student→slot links use `set null` /
  `restrict` respectively (never `cascade`), so removing a slot or student can never
  cascade-delete billing history (D-06). Verified by the onDelete grep in Task 1.
- **Money integrity:** the amount formula is centralized and unchanged (integer cents,
  single Math.round) — extraction introduces no rounding drift; guarded by the
  behavior-unchanged acceptance criterion.
- No new external input, no auth surface, no secret handling in this plan.
</threat_model>
