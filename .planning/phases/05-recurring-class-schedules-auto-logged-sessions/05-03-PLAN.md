<objective>
Deliver the daily auto-log job (SCHED-03) and its secure delivery: an idempotent catch-up
engine, a constant-time `CRON_SECRET` bearer check, the `/api/cron/auto-log` route handler,
the `vercel.json` cron schedule, and the `middleware.ts` exemption that lets the scheduler
reach the route while keeping it un-triggerable by the public (SC4).

The engine (`runAutoLog`) processes each (slot, calendar-date) **exactly once, ever** via the
per-slot `lastLoggedDate` high-water-mark (D-05), so a deleted auto-session stays deleted and
a skipped/late Hobby-plan run self-heals (RESEARCH §1–§2). Amounts freeze from the student's
current rate through the shared `computeAmountCents` helper (Plan 01) — auto-sessions are
data-identical to manual ones.

Wave 2 (depends on Plan 01's schema + amount helper). Parallel with Plans 02 and 05.
</objective>

  <action>
    Create `lib/schedule/auto-log.ts` (plain async module — NOT "use server"; it is called by
    the route handler, not a form). Export `async function runAutoLog(): Promise<{
    processedSlots: number; sessionsCreated: number }>`.
    Steps:
    1. Resolve timezone once: read the settings row; `tz = settings?.timezone ?? DEFAULT_TIMEZONE`.
       `const today = todayInZone(tz)`.
    2. Load all slots (join or two queries) with their student's CURRENT rateCents. A slot's
       student may be archived — still log (archived students keep history; billing decisions
       are downstream). Skip a slot whose student row is missing (defensive).
    3. For EACH slot, compute the window: `lower = slot.lastLoggedDate ? nextDay(slot.lastLoggedDate)
       : slot.effectiveDate` (nextDay = add one calendar day as a string); `upper = today`.
       If `lower > upper` (string compare works for yyyy-MM-dd), skip the slot (nothing new).
    4. `for (const d of eachDateInclusive(lower, upper))` where `weekdayOf(d) === slot.weekday`,
       build an insert row: `{ studentId, date: d, durationMinutes: slot.durationMinutes,
       amountCents: computeAmountCents(slot.durationMinutes, student.rateCents), notes: null,
       billed: false, scheduleSlotId: slot.id }` (D-04: stamp the slot; notes stays blank per D-04).
    5. Atomicity (neon-http compatible): collect ALL matching insert rows for the slot into a
       JS array FIRST (steps 3–4, no DB access), then `await db.transaction(async (tx) => { if
       (rows.length) await tx.insert(sessions).values(rows); await
       tx.update(scheduleSlots).set({ lastLoggedDate: upper }).where(eq(scheduleSlots.id,
       slot.id)); })` — a fixed two-statement batch with no intermediate reads (the neon-http
       driver requires this shape; do not SELECT or branch inside the callback). This makes a
       crash mid-slot commit nothing so a re-run retries cleanly — the HWM only advances if the
       inserts also committed (RESEARCH §2), which is what guarantees no duplicate on re-run.
       Always advance lastLoggedDate to `upper` even when the window had no matching weekday (so
       the HWM keeps moving and future runs don't re-scan old dates).
    6. Return counts for logging. Never throw for a single bad slot — collect and continue so
       one student's issue doesn't block the rest; surface a summary the route can log.
    Do not reference request/timezone from any client input — tz comes only from settings.
  </action>

<threat_model>
ASVS L1 — this plan introduces the phase's only externally-reachable, login-gate-exempt route,
so it carries the highest attack surface. **Block-on: high.**
- **[HIGH] Publicly-triggerable data mutation:** /api/cron/auto-log is exempt from the login
  gate (D-09). Mitigation: the route's FIRST action is a constant-time `CRON_SECRET` bearer
  check returning 401 on any mismatch (Task 2/3); the secret is ≥16 random chars, lives only in
  env (never code), and Vercel injects it automatically. Verified by the "unauthenticated → 401"
  acceptance criterion. Residual: none beyond secret custody (rotate via Vercel env).
- **[HIGH] Middleware auth-bypass (CVE-2025-29927):** affects Next 11.1.4–15.2.2; this app is on
  16.2.10 (patched). Defense-in-depth: cron auth does NOT rely on middleware — the route enforces
  its own bearer check, so even a middleware bypass cannot trigger the job. The matcher change
  exempts ONLY `/api/cron` (narrow negative-lookahead), so no app/data route loses its gate.
- **[MED] Duplicate / double-logging (billing integrity):** the per-slot `lastLoggedDate` HWM +
  per-slot transaction make each (slot, date) process exactly once even under retries, concurrent
  invocations, or Hobby-plan re-fires. Verified by the observed-idempotency acceptance criterion.
- **[MED] Timezone off-by-one → wrong class day:** class-day resolution uses `todayInZone` +
  UTC-anchored `weekdayOf` (never local getDate/getDay), with an America/New_York fallback when
  settings.timezone is null → no midnight/DST drift.
- **[LOW] Info leak on error:** the route returns a generic 500 and never logs the secret.
- **[LOW] Timing attack on the secret:** mitigated by `timingSafeEqual` constant-time compare.
</threat_model>
