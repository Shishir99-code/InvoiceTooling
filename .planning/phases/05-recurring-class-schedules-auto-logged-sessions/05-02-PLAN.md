<threat_model>
ASVS L1 — server actions behind the existing iron-session login gate (no new public surface;
the cron route is Plan 03).
- **Injection / mass-assignment:** every action parses through zod `slotFormSchema` and
  `.pick`s only the four form fields; server-assigned columns (effectiveDate, lastLoggedDate,
  id) are never taken from FormData → a forged `effectiveDate`/`lastLoggedDate` in the payload
  cannot backdate or reset the high-water-mark. Mitigated by the `.pick` and the source
  assertion in Task 3.
- **IDOR on edit/delete:** single-user app (one shared password), so cross-tenant IDOR is
  out of the trust model; the positive-int id guard still prevents malformed ids from reaching
  the DB.
- **History tampering (D-06):** deleteSlotAction/editSlotAction never write to `sessions`;
  the `set null` FK preserves rows. Guarded by the `! grep delete(sessions)` acceptance check.
- **Timezone spoofing:** timezone is read from the trusted settings row, never from client
  input — a client cannot shift effectiveDate by supplying a zone.
- No secrets handled in this plan.
</threat_model>
